# Additive widget release verification

Use `swift test`, `./Scripts/build_app.sh` and `./Scripts/package_dmg.sh`; verify the built bundle with `codesign --verify --deep --strict dist/EventViewer.app`. Bind source, tests and independent review to the same source manifest before release. Render tests must independently create their output directories; never rely on test execution ordering.

For desktop inspection copy the candidate into a separate QA app under `.build/WidgetQA`, give it bundle ID `com.loweffort.eventviewer.widgetqa` and name EventViewer Widget QA, then re-sign it. Stop only that exact QA executable before refreshing it. Do not replace the installed application or write its preference domain. Hash canonical sorted preference exports privately before/after and retain only hashes.

If ScreenCaptureKit reports -3811, check whether the Mac is unlocked and the QA main window is visible on an active display. In this session, refreshing and foregrounding only the QA bundle restored capture after unlock; no privacy permission changes were needed. Foreground activation through `open` was explicitly authorized for the QA app. Do not infer permission failure from -3811 alone. Close the QA main window to target the floating Card for native inspection; closing the Card returns to the retained main-window accessibility target. Synthetic drag/keyboard input can fail silently: record observed results and leave physical movement or multiple displays unverified unless actually exercised.

Check gallery selection, Cancel without addition, Add once, all eight graph styles, close/re-enable and adaptive/fixed overflow. Inspect both native render fixtures and the actual desktop UI. `ImageRenderer` of the lazy gallery left its grid blank; discard blank exports. The eager showcase built from actual Card views is an accurately labelled native sample preview, not desktop interaction evidence. Publish only sample data and distinguish native capture from product-view rendering in captions.

Release through the reviewed PR and passing CI, then an ordinary new tag at the verified merged revision. Never use the legacy force-tag helper. Verify source and distribution release assets match, mount the downloaded DMG read-only, check version/build/signature, and verify public download access. Coordinate website screenshot publication after release; verify Azure workflow, live HTML and exact public asset hashes separately. Dispatch success alone is not deployment proof.
